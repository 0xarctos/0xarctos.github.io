### [Reading checksec](/kb/reading_checksec/)

* Partial RELRO
* No canary
* No PIE (base address 0x400000)

This enables ROP and GOT overwrite without requiring any leak.

### [Strings](/kb/strings/)

There is a clear reference to the flag: 
```
00402039	flag.txt missing	"flag.txt missing"	ds
```

``0x402039`` leads to the ``managerOverride`` method

``managerOverride``:
* opens, reads and displays the flag.
* expects an argument and compares it with the magic ``0xc0ffee`` in order to give the flag.
* is not called anywhere.

### Hypothesis

The challenge asks us to build a ROP chain in order to jump into ``managerOverride`` providing the correct argument.

### [Vulnerabilities](/pwn/common_vulnerabilities/)

``checkout`` method has a local buffer of ``64`` bytes then performs a ``read`` call in it with a max length of ``256`` (0x100) bytes.

### [The Stack](/pwn/the_stack/)

The vulnerable buffer starts at ``$rbp - 64`` (0x40), meaning that saved rbp then return address are right after the buffer on the stack. 
This means that can overflow the buffer to overwrite the saved rbp and the return address then we can input ``176`` more bytes for our ROP chain.

So, our ROP-chain max length is about 23 words starting on the return address.

### [Gadgets](/pwn/rop_gadgets/)

To perform our ROP attack we need as gadgets:
* ``pop rdi; ret;``: inject the expected magic number as first argument for ``managerOverride``.
* ``ret;``: maintain 16-byte stack alignment.

The binary itself has the perfect gadgets:

```bash
$ ROPgadget --binary blue_market | grep "pop rdi"
0x0000000000401182 : pop rdi ; ret

$ ROPgadget --binary blue_market | grep "ret"
0x0000000000401016 : ret
```
